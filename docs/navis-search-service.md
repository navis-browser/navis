# Navis search ownership

`NavisSearchService.sys.mjs` is the shared Core-private adapter used by desktop and Android. Platform receives frozen provider/default/consent values and URL strings. Gecko `SearchService`, `UserSearchEngine`, `SearchSettings` and `SearchSuggestionController` own engine interpretation, ordering, defaults, submission encoding, atomic Profile storage and suggestion transport.

`NavisSearchPolicy.sys.mjs` supplies the offline Google, Bing, Baidu and DuckDuckGo catalogue. Providers keep editable names and HTTP(S) search templates; suggestion templates are optional. All four built-ins have OpenSearch-compatible JSON suggestion endpoints. Baidu uses `https://www.baidu.com/su?ie=utf-8&action=opensearch&wd={searchTerms}` through the same shared suggestion service as the other providers. A separate one-time metadata marker upgrades already-imported Profiles only where Baidu retains its original search URL and has no suggestion endpoint. Names, ordering, default, consent and custom URLs are preserved. Old releases did not distinguish an omitted endpoint from a manually cleared empty value; the migration backfills that matching empty record once. A subsequent explicit clear survives restart. Fresh imports mark the correction complete in the original atomic write, preserving explicit empty legacy values. Failed upgrade writes roll back the live endpoint and retry without resetting the original provider migration. A provider without an endpoint never starts a suggestion request. Configured endpoints remain subject to the consent and request rules below; configuration does not guarantee external provider availability.

The adapter imports the former Navis provider preference records once. Stable provider IDs and original display names are engine metadata; order, templates and defaults use Gecko's existing state. Gecko requires unique engine names, so a duplicate display name receives a disambiguated internal name while its original display name remains visible through the adapter. Edited built-in search templates receive no suggested endpoint unless explicitly configured. The import marker and suggestion consent live in the same `search.json.mozlz4` atomic write as the engines. Old preference data is a migration input only; subsequent changes go through SearchService.

Initialization and mutations await Gecko's atomic settings writer. A failed write rejects, restores the writer's previous cache and rolls back the public mutation. Migration failures can retry with the original input; the marker is not committed early. The underlying Gecko service retains its upstream terminal state for failures during its own initialization. Missing package or host dependencies require correcting that failure and restarting the runtime. Desktop Runtime currently treats an initial `ready` rejection as a failed startup and requires relaunch. Adapter migration retry is available to callers that explicitly retry initialization; it is not a desktop startup recovery UI. Ordinary post-startup mutation failures leave Runtime readiness intact and can be retried after the write failure is resolved.

Remote suggestions default off. Both the adapter and Gecko controller require saved Profile consent, a configured endpoint, ordinary query text and a nonprivate request. URLs, network addresses and paths are rejected before a controller creates network activity. Gecko supplies anonymous requests without cookies or persistent caching. Aborted or superseded requests return no results; changing consent, provider settings or defaults cancels outstanding requests. The adapter never requests Gecko FormHistory results; Platform local candidates use the separate shared local ranking policy.

Under `MOZ_NAVIS_CORE`, stored Profile consent is the sole suggestion opt-in; the retained controller does not also require the legacy `browser.search.suggest.enabled` preference. Android inherits that preference's false default, which previously suppressed every request even after Navis opt-in. Non-Navis products retain their original preference behavior. The Android bridge/controller regression exercises this exact false-default case.

Core sets Gecko's suggestion deadline to a 2000 ms default when the shared service is first acquired, allowing headroom for cold DNS/TLS setup. Explicit user preference overrides are preserved; initialization never persists a user preference. Local candidates remain immediate, remote input is debounced by 250 ms, and new input or dismissal cancels the previous request without waiting for this deadline. Desktop and Android use this same Core default.

Semantic port 0107 restores the search JavaScript graph with the `MOZ_NAVIS_CORE` product seam. Mozilla's Rust/Remote Settings selector and the unused search-autocomplete component remain outside the Navis package. Passive upstream OpenSearch modules and engine-type classes remain present. Remote-configured engines cannot be constructed, and their normally eager icon subscription is disabled. Region, locale and experiment reloads, enterprise migrations, OpenSearch timers, extension engine installation and Places favicon loading do not activate. The existing observability-disabled Gecko facade remains inert. Other Gecko products retain their upstream path. This port changes JavaScript and build directory/resource selection only; it adds no native source or Rust crate.
